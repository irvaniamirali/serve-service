# Contributing

## Working Principles

- Read the roadmap and the active milestone document before making changes.
- Keep changes focused on the current milestone unless a dependency requires otherwise.
- Add or update tests for behavior changes.
- Update documentation when behavior, configuration, or operational procedures change.
- Never commit credentials, tokens, private keys, local environment files, or generated artifacts.
- Document important architectural choices in `docs/decisions/`.

## Definition of Done

A task is done when its behavior is implemented, relevant tests pass, documentation is updated, and known limitations are recorded.

## Milestone Status

Do not mark a milestone complete solely because implementation has started or code has been written. Its acceptance criteria must be verified.
